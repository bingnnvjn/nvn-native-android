## 0. 三条读表规则

1. **不改门**：本表任何一行都不改变 M0a–M3b 的红绿。要改门，另开票。
2. **概率只标依据**：数据 / 推断 / 待测。待测 = 未定，不写百分比、不参与排序。
3. **判定点两种写法**：编号引用（`GATES §x.y/字段`、`PIPELINE §4.3.n`），或四元组 {执行人, 命令/事件, 阈值, 记录位置}。两者都不产生门红绿。

**今天的状态**：`nva_stats` 仍是 v1 的 9 个负载字段；GATES §2.4 的 9 个追加字段与设备门执行物都还不存在（GATES §0 自认）。所以下表挂在设备门上的判定点，今天只能记录，不能签。

**排序**：影响（①可玩 ＞ ②发布 ＞ ③TotK）→ 判定点（门序）→ 证据等级（数据 ＞ 推断 ＞ 待测）。

## 2. 每条风险的触发动作

| # | 触发后做什么 | 备注（为什么不能更简单） |
|---|---|---|
| 1 | **换路线**：改内存架构（zero-copy / AHB），不降画质、不改门 | M3a 没有绝对内存水位，会「绿着爆」；降纹理精度会动 M2a/M3b 冻结的像素与 pipeline key |
| 2 | 翻译失败 → 修翻译器；驱动失败 → 换 SPIR-V 形态或换驱动；只有「M3a 最后 300 秒用到且只能跳过」才另开票谈白名单 | `missing_variants` 只定义「缓存未命中」，看不见 `vkCreateGraphicsPipelines` 失败 |
| 3 | **换路线**：实现符号解析；解析不了 → 该 build 放弃 | 过场动画本身按 `GATES §6.2` 登记为条件门，不占名额 |
| 4 | **不预设**：红了先归因。热 → 降级票；优化不足 → 引擎票；都不是 → 冷启复跑一次再升级 | 「固定节流」启发式不可用（按字面惩罚「帧时间稳」）；M3a 没有固定路线，30 min 不可复现 |
| 5 | 修实现，不改门；另开 `GATES §7.2` 修订票 | 「仍可恢复」今天没有定义；两条判据共用 kill 点会互相误杀 |
| 6 | 修实现；5.1 另开票 | ARCH 已把 v1 音频定成 48 kHz / 2ch；5.1 是缺口，不是选项 |
| 7 | 实现该槽；**不扩白名单** | 523 是 d2r 的 core+debug 表；BotW `sdk` 另有 27 个 NVX 名字不在表内 |
| 8 | 记录型，不阻断门；**不得写 validation clean** | #31 未关，按已知差距记 |
| 9 | 换路线（语义站点映射）或维持手工表 | 真选择落在 TotK 1.4.3 评估；#24 已把它排在 1.2.1 验收之后 |

## 4. 需要另开的票

1. **ABI 追加票**：GATES §2.4 的 9 个设备计数字段 + `pipeline_create_failed` + 内存水位字段。
2. **`GATES §7.2` 修订票**：把存档判据写成两段（存完 kill / 写入中 kill）。
3. **`GATES §6.2` 修订票**：`codec_calls` / `movie_open` 不在 §2.4 清单里，探针没有载体。
4. **预热步定义票**：ARCH 说翻译全在构建期，#14 说设备端预热；GATES 里没有这一步。
5. **M3a workload 票**：钉死路线 / 机位 / 输入序列，否则 30 min 不可复现。
6. **ARCH 勘误**：POSIX `rename` 不能覆盖非空目录，「整体 rename」要改成版本目录 + 原子指针。
7. **§7.2 SAF 口径扩展**：1 GB → 15.1 GB 全量。
8. **NVN 分母票**：523 是 d2r 的表，BotW `sdk` 另有 27 个 NVX 名字。
9. **内存观测票**：`nva_stats` 尾部追加水位字段，让 M3a 能看见绝对水位。
